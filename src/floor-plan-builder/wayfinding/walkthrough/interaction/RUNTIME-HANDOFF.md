# Runtime handoff (A6)

Implementation is confined to interaction/ and ui/. WalkthroughLayer.tsx remains owned by its current editor. Its existing queue handlers continue to work; new bench/kiosk handlers require the following handoff.

1. Create one `WalkLocalActions` per pinned playback session and explicit role. Supply `allowedRoles: ['staff', 'visitor']` only for the approved local demo policy. Omission denies every local use. This is presentation/runtime policy, not authentication or an inferred source ACL.
2. Supply actual menu `items` and elevator `destinations` keyed by **descriptor id** (`instance:<floor>:<object>`). Entries are `{ id, label }`. No source menu exists in the current adapter: do not invent stock or prices. Missing menus visibly disable browse/order.
3. Pass that owner as `localActions` to `new ProximityInteractionRuntime`. Remove the layer's old join/leave/call handlers from `handlers`: duplicate capabilities deliberately fail closed. Pass `localActions.handlers()` and the same interaction descriptors to registry construction if availability is displayed there. Keep unrelated handlers.
4. Keep rendering `InteractionPrompt` with current target/state. Its local child subscribes to the owner. Continue `update` after resolved motion; demand rendering must continue through the dwell window (350 ms default). Updates use world coordinates and walker yaw (-Z forward).
5. `applyBenchStance(target, stance)` is synchronous and atomic: stop motion, validate current full-capsule sweep and destination/support against the current world, apply the actual supported physical stance, update avatar and camera, then return true. Return false without applying on rejection. Retain bench collision. On standing, validate full standing capsule and exit. While seated suppress walking/auto travel; stand successfully before resuming. Do not reset the owner or change floors while seated. No callback means seating is unavailable.
6. Bench metadata currently has no seat socket and a solid 1.8 x .45 x .5 m collider. An upright capsule at its center is not a safe seat. A supported stance/collider model is an external prerequisite; boolean availability from metadata is insufficient.
7. Elevator destination selection is display-only pending actual physical connector integration. Ride action always reports unavailable before confirmation; no local offer/completion is represented as passenger traversal. Replace this only in a separately owned connector integration that revalidates shaft, apertures, cabin, doors, endpoints and swept motion at confirmation.
8. Door callbacks remain owned by the layer. Only close collision after the capsule clears; runtime proximity exit and `clear()` are requests, not proof of physical clearance.

Transitions: queue join requires runtime confirmation and is idempotent; leave is immediate. Kiosk browse -> select -> runtime confirmation -> local order created. Cancel resets an uncompleted selection. Changing selection cancels runtime confirmation. Completed local orders remain session-local and cannot be cancelled. Bench state changes only after physical acceptance. Clear focus/session teardown invalidates confirmation, never changes the document.

Selection is nearest/front with 0.3 m switching hysteresis, 0.5 m exit range hysteresis, and separate door proximity. Async inspect/use results are ignored after focus changes. Visitor projection permits company/category/booth name/number/public description; contacts/internal notes are staff only, unknown roles project nothing. Missing fields remain absent.

Verification boundary: source checks do not demonstrate actual seating, connector traversal, door collision timing, or a fresh live Lab pass. The layer handoff above is required before claiming the new controller is mounted.
