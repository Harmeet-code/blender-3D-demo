## Problems corrected in the inherited implementation

- Hole triangulation could index outside the outer ring; it now uses the combined contour/hole vertex list. Hole containment, intersections and net area are validated.
- Post-build nearest-polygon area painting could change the area of a much larger Detour polygon than the authored zone. The same Recast worker now marks compact-heightfield areas before region/contour generation. Cached mesh identity includes area content and the agent profile, including removal of all areas. Existing calls without wayfinding options keep their previous build profile.
- Query filters are released after each query. Diagnostic island sampling is bounded and omitted from repeated endpoint/routing input builds.
- Stacked-floor funnel points previously inferred floor ownership from nearest XZ, which is ambiguous at stacked landings. Ownership now follows the original route leg.
- Route results now retain floor elevation and explicit connector legs; length and ETA use the actual displayed route, and connector instructions name the target floor.
- Missing accessible options no longer fall back to a shortest route through stairs. Legacy stairs/escalators are excluded while authored ramps remain eligible.
- Booth openings account for baked scale, nearest approach and exterior clearance; closed booths get an exterior-stop warning. Object picks resolve to item access points, rather than clicking an arbitrary roof/centre point.
- Worker point/floor counts and finite coordinates are checked at the studio boundary. Route clearing cancels pending work and invalidates late results; document changes clear session route state.
- Search text is owned by `CommandInput`, with grouped inventory results and an explicit accessible label. It is not confused with cmdk's selected-item value.
- Ribbon camera updates no longer allocate new geometry; old fades continue with effects paused. Roof ghosting no longer forces objects into their top-view rendering mode.

### Phase 3 evidence

- Standalone TypeScript, focused lint/format checks, and production build passed. The build retains the existing large-chunk warning.
- In-memory measurements using the actual compiler/follower: on a straight segment with uneven waypoint spacing, 30/60/144 Hz updates produced 1.20 m/s at 1× and 4.80 m/s at 4×. Start/end easing and turns intentionally reduce speed.
- Complete straight walk, stair ascent/descent, and ramp ascent/descent measurements at 1× and 4× reached their destinations. A Three.js skeleton with the inventory rig's bone positions measured maximum stance-foot-to-anchor error below `2e-15 m` after the pelvis correction. This verifies the IK constraint in these fixtures, not every possible custom layout or visual animation transition.
- Zero-length routes arrive without NaN progress. An elevator with `running=false` rejects playback with an out-of-service explanation.
- Live browser checks used the real worker: hall playback; stairs and upper-floor arrival; a valid 1.2 m-rise ramp and accessible route; escalator stand-and-ride; elevator ride and cabin framing; POV body hiding; comfort; pause/restart/skip/scrub; keyboard mode changes and scrubbing; moving/removing a planter; keeping the pinned path; and accepting a replacement route.
- The development React Profiler counter stayed at **3 scene commits** while distance advanced from the start to approximately 28% of the ramp scenario's route. Pausing added a coarse-state commit. HUD snapshots did not cause a scene commit per frame.
- The development camera restoration audit reported **0 m position error and 0 rad orientation error** after leaving chase/POV. The original camera object, projection settings, zoom and control target are restored.
- No automated test files were added for this phase, following the user's instruction to skip tests.

### Remaining limits

- Phase 4 below supersedes this performance deferral. The hardware-wide 60 fps target and isolated sub-200 ms rebuild remain unverified.
- Camera collision uses conservative canonical polygons rather than a Rapier world. Arbitrary newly inserted obstacles directly over the pinned avatar, custom connector misalignment, and all combinations of resize/DPR changes during transitions have not been exhaustively exercised.
- Rich zone persistence and its complete authoring UI retain the Phase 1/2 limitations described above. Playback works locally without backend persistence.
- The synthetic gait measurements cover the stated fixtures; subjective animation quality across arbitrary custom scenes still needs user review.

### Performance evidence and its limits

Fixture: /admin/floor-plan?wayfindingPreview=1&scenario=performance. It contains 300 objects (20 booths, 40 planters, 240 chairs), a 90 m route and the walkthrough avatar. This deliberately mixed fixture is not a guarantee for every 300-object inventory mix.

The original 2026-10-19 sample at a 992 × 415 canvas, DPR 1, used the now-removed composer/WebGL minimap: High 16.8 ms/frame, CPU render 11.5 ms, 1,715 draws, 215,385 submitted triangles, six passes, 20 visitors; Off 16.7 ms/frame, CPU render 4.1 ms, 648 draws, 55,440 triangles, zero passes/visitors. These measurements are retained as superseded evidence, not acceptance results for the corrected renderer. The earlier pre-batching sample was 41.4 ms/frame and 10,686 draws.

Corrected-renderer measurements are recorded in PHASE-4-REVIEW.md. CPU render is JavaScript submission time, not GPU execution or whole-frame cost. Draw/triangle counters include shadow/transmission work; they are not unique model counts. Comparing complete tiers also changes visitors/shadows/transmission, so it does not isolate one effect. All corrected tiers have zero postprocessing passes.

The universal mid-range-laptop 60 fps target and an isolated sub-200 ms navmesh rebuild remain unverified. Worker routing timing includes mesh and query work and is labelled accordingly.
